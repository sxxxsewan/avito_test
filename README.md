# Avito bot detection

Решение использует поведенческие признаки и локальную open-source библиотеку CatBoost; внешние API не нужны. Финальный `score` — среднее процентильных рангов трёх CatBoost-моделей с seed `42`, `17` и `2025`. `target` используется только при обучении и не участвует в расчёте признаков.

## Запуск

Рекомендуемая версия Python: **3.12.0**.

```powershell
py -3.12 -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python solution.py
```

По умолчанию скрипт проверяет baseline, HistGradientBoosting и ансамбль CatBoost на трёх последовательных временных окнах по метрике из `metric.py`, затем обучает ансамбль на всём train и сохраняет `submission.csv`. Файл содержит только `cookie_id` и `score`.

Отдельные режимы:

```powershell
python solution.py --mode validate
python solution.py --mode submit --output submission.csv
```

Путь к папке с `train.csv`, `test.csv` и `events.csv.gz` можно задать через `--data-dir`. Скрипт не скачивает данные из сети; перед запуском исходные файлы задачи должны быть распакованы в `data/`.

### Запуск из ноутбука

`avito_solution.ipynb` — самостоятельный вариант решения: он содержит построение признаков, обучение трёх CatBoost-моделей и сохранение `submission.csv`, не импортируя `solution.py`. Ноутбук использует тот же каталог `data/` и зависимости из `requirements.txt`. Его набор признаков расширен относительно скрипта; поэтому метрики и полученные им прогнозы не следует считать побитово эквивалентными результату `solution.py`. `quickstart.ipynb` — первоначальный учебный пример, а не финальный pipeline.

## Признаки и временная граница

В обоих вариантах признаки строятся только по событиям с `window_start_ts <= event_ts < window_end_ts`. Полные дубликаты исключаются из поведенческих агрегатов; их число сохраняется как диагностический признак, но не подаётся модели. В `solution.py` числовые пропуски HistGradientBoosting заполняются медианой, а категории кодируются `OneHotEncoder`; CatBoost получает категории нативно и не использует этот OneHot-кодировщик. Скрипт учитывает частоты и разнообразие событий, временные интервалы, активные часы, поиск, указатель, User-Agent и возраст cookie. Высококардинальные ID объявлений и текст поискового запроса напрямую в модель скрипта не передаются.

В `avito_solution.ipynb` дополнительно рассчитываются регулярность интервалов и длинные паузы, активные минуты, последовательности типов событий, концентрация просмотров на объявлениях, статистики длины и версии User-Agent, поискового поведения и движения указателя. Это отдельная расширенная версия признаков; она не меняет реализацию `solution.py`.

## Валидация и эксперименты

Проверяются три последовательных временных окна, не перемешивая куки случайно. На каждом окне сравниваются простой baseline, HistGradientBoosting, CatBoost с одним seed и CatBoost rank-average по трём seed:

- 6–10 апреля → 11–13 апреля;
- 6–13 апреля → 14–16 апреля;
- 6–16 апреля → 17–19 апреля;
- baseline использует только количество событий и уникальных объявлений (`n_events`, `n_items`);
- обе модели используют отобранные временные, поведенческие, категориальные и User-Agent признаки.

В `solution.py` сравниваются baseline, HistGradientBoosting, CatBoost с одним seed и rank-average трёх seed. Указанные ниже значения — сохранённые результаты локальной валидации этой версии скрипта; они не являются метрикой расширенного ноутбука или скрытого теста. Ранг-ансамбль CatBoost улучшил `P@R>=0.70` относительно одиночного seed на этих трёх окнах:

| Окно | Baseline P@R | HGB P@R | CatBoost, seed 42 | CatBoost, 3-seed rank average |
| --- | ---: | ---: | ---: | ---: |
| 11–13 апреля | 0.0961 | 0.5128 | 0.5983 | 0.6195 |
| 14–16 апреля | 0.1243 | 0.6402 | 0.6216 | 0.6832 |
| 17–19 апреля | 0.1232 | 0.6829 | 0.7044 | 0.7244 |

Средний `P@R>=0.70` ансамбля на этих folds — 0.6757. Локальные метрики были получены в Python 3.14.0, CatBoost 1.2.10, scikit-learn 1.9.1, pandas 3.0.6 и NumPy 2.5.3; `requirements.txt` закрепляет версии для Python 3.12. Валидационные числа не гарантируют такой же результат на скрытом тесте. Финальный ансамбль скрипта переобучается на всём train.
